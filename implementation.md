### 2.2 API Client (`src/lib/api/client.ts`)

Create a **fetch-based** API client with the following capabilities:

```typescript
// Base configuration
const API_BASE = process.env.NEXT_PUBLIC_API_URL || "http://localhost:5000/api";

// The client should:
// 1. Automatically attach Authorization header if token exists
// 2. Automatically set Content-Type: application/json
// 3. Include credentials: "include" for cookie handling
// 4. Parse response and return typed data
// 5. Handle errors consistently (throw with ApiError shape)
// 6. Support 401 → automatic token refresh → retry pattern
```

**Key implementation details**:

1. **Token storage**: Use a Zustand store (see Phase 3) to hold the access token in memory. The API client reads from this store.
2. **Refresh interceptor**: On 401 response, call `POST /api/auth/refresh-token` (with cookies). If it returns a new token, update the store and retry the original request. If refresh also fails, clear auth state and redirect to `/auth/login`.
3. **Error transformation**: All non-2xx responses should throw a structured error that components can catch and display.

**Functions to export**:

```typescript
export async function apiGet<T>(path: string, options?: RequestInit): Promise<ApiResponse<T>>
export async function apiPost<T>(path: string, body?: unknown): Promise<ApiResponse<T>>
export async function apiPut<T>(path: string, body?: unknown): Promise<ApiResponse<T>>
export async function apiPatch<T>(path: string, body?: unknown): Promise<ApiResponse<T>>
export async function apiDelete<T>(path: string): Promise<ApiResponse<T>>
```

### 3.4 Next.js Middleware (`src/middleware.ts`)

Create a middleware that:

1. Checks if the route is protected (starts with `/dashboard`)
2. Checks if the `refreshToken` cookie exists
3. If no cookie and route is protected → redirect to `/auth/login`
4. If cookie exists and route is auth page (`/auth/login`, `/auth/register`) → redirect to `/dashboard/tenant` (or appropriate dashboard based on role)

**Important**: The middleware **cannot** check the role from the JWT (the access token is in memory, not in cookies). Role-based route protection is handled at the **layout level** (see Phase 5/7/8). The middleware only checks for the presence of the `refreshToken` cookie as a proxy for "logged in."

```typescript
import { NextResponse } from "next/server";
import type { NextRequest } from "next/server";

export function middleware(request: NextRequest) {
  const refreshToken = request.cookies.get("refreshToken");
  const { pathname } = request.nextUrl;

  const isAuthPage = pathname.startsWith("/auth");
  const isDashboard = pathname.startsWith("/dashboard");

  if (isDashboard && !refreshToken) {
    return NextResponse.redirect(new URL("/auth/login", request.url));
  }

  if (isAuthPage && refreshToken) {
    return NextResponse.redirect(new URL("/dashboard/tenant", request.url));
  }

  return NextResponse.next();
}

export const config = {
  matcher: ["/dashboard/:path*", "/auth/:path*"],
};
```

### 3.5 Logout Function

Create a logout handler that:

> **Note**: The backend does NOT have a logout endpoint. Logout is client-side only — clear the access token from memory and delete the refreshToken cookie. The cookie can be cleared by setting `document.cookie = 'refreshToken=; Path=/; Expires=Thu, 01 Jan 1970 00:00:00 GMT;'`.

## Key Technical Decisions Summary

| Decision | Choice | Rationale |
|----------|--------|-----------|
| **State Management** | Zustand (auth) + TanStack Query (server state) | Minimal boilerplate, excellent caching, works well with Next.js |
| **Form Handling** | React Hook Form + Zod | Assignment requirement (mandatory) |
| **API Client** | Custom fetch wrapper | Full control over interceptors, no axios dependency |
| **Token Storage** | Access token in memory (Zustand), refresh token in httpOnly cookie | Security best practice — tokens not accessible via XSS |
| **Styling** | Tailwind CSS with custom design system | Assignment requirement |
| **Route Protection** | Next.js Middleware (cookie check) + Layout-level (role check) | Two-layer protection for security |
| **Payment** | Stripe Elements (@stripe/react-stripe-js) | Assignment requirement, uses clientSecret from backend |
| **Image Optimization** | next/image with remote patterns | Performance requirement |
| **Toast Notifications** | sonner | Lightweight, beautiful, easy to use |
| **Icons** | lucide-react | Comprehensive, tree-shakeable, consistent |
